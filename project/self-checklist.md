# Самопроверка проекта (self-checklist)

Отметьте, что реализовано в вашем проекте.
Этот чеклист помогает и вам, и преподавателю быстро понять, на каком уровне готовности находится проект.

В столбце «Да/Нет (студент)» поставьте `✅` или `❌`.
В столбце «Где смотреть / комментарий» укажите файл(ы), где реализован соответствующий пункт.

> Важно: чеклист – это **самооценка**. Преподаватель может не согласиться с вашими отметками и скорректировать оценку.

## Подсчёт баллов и связь с оценкой

За каждый критерий, по которому вы честно можете поставить `✅`, засчитывается **1 балл**.
Максимум – 10 баллов.

**Результат самопроверки: 10 / 10 баллов.**

Преподаватель использует суммарное количество баллов **после проверки** в качестве ориентира для выставления оценки:

- Если проект **не проходит базовый минимум** (не запускается, отсутствует ключевой функционал, грубые нарушения, плагиат и т.п.) – оценка: **2** (проходной минимум не достигнут).
- Если минимум пройден, то ориентировочно:
  - **1-4 балла** → оценка **3** (проект принят, но на базовом уровне);
  - **5-8 баллов** → оценка **4** (хороший, рабочий проект);
  - **9-10 баллов** → оценка **5** (сильный, хорошо проработанный проект).

Окончательное решение по оценке остаётся за преподавателем и может учитывать:

- качество реализации внутри каждого пункта;
- дополнительные сильные стороны проекта (нестандартные решения, дополнительные функции, аккуратная архитектура и т.п.);
- соблюдение требований курса и дедлайнов.

## Дополнительные сильные стороны проекта

- **Тюнинг гиперпараметров** через `GridSearchCV` (5-fold StratifiedKFold, ROC-AUC), сетки вынесены в `configs/config.yaml` — эксперимент перенастраивается без правки кода.
- **Нейросетевой бейзлайн (MLP)** поверх того же препроцессора — честное сравнение классических моделей и нейросети с выводом, почему для табличных данных выбран бустинг.
- **Подбор порога классификации по F2** на out-of-fold предсказаниях train (без утечки теста): recall финальной модели вырос с 0.51 до 0.89 — осознанная оптимизация под бизнес-метрику.
- **MLflow-трекинг**: все 8 прогонов (параметры + метрики) логируются в `mlruns/`, можно смотреть через `mlflow ui`.
- **Pipeline-объект** в `joblib.dump`: препроцессор и модель сохраняются вместе, что исключает рассинхронизацию обработки данных между обучением и инференсом.
- **Pydantic-схемы** с `Literal[...]` для категориальных полей дают строгую валидацию входа на уровне HTTP (422 для невалидного значения).
- **Lifespan** вместо устаревшего `on_event("startup")` — соответствует современному API FastAPI/Starlette 1.0.
- **HEALTHCHECK** прописан прямо в `Dockerfile`, контейнер сообщает о своём состоянии оркестратору.
- **10 pytest-тестов** (5 на данные/препроцессор + 5 на сервис, включая проверку согласованности порога сервиса с артефактом обучения), все проходят.
- **Обучение модели на этапе `docker build`**: сериализованный Pipeline гарантированно совместим с версиями библиотек контейнера (исключён классический сбой «pickle обучен другой версией sklearn»); seed зафиксирован — результат детерминирован.
