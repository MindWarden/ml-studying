# HW13 – токенизация текста, инференс BERT и базовый fine-tuning для классификации

## 1. Кратко: что сделано

- **Датасет**: `emotion` (HuggingFace) — классификация эмоций в коротких англоязычных текстах. Выбран как рекомендованный по умолчанию, хорошо сбалансированный датасет с понятными 6 классами.
- **Модель для fine-tuning**: `distilbert-base-uncased` — компактная дистиллированная версия BERT, быстро обучается, хорошо работает на CPU/GPU.
- **Модель для инференса (готовая)**: `bhadresh-savani/distilbert-base-uncased-emotion` — DistilBERT, уже обученный на датасете emotion.
- **Токенизация**: показана с `AutoTokenizer` для `distilbert-base-uncased` — продемонстрированы tokens, input_ids, attention_mask, padding и truncation на 5 примерах.
- **Инференс готовой модели**: запущен через `pipeline("text-classification")` на 5 примерах из test, а также вручную (logits → softmax) на 1 примере.
- **Fine-tuning**: 3 эпохи на 2000 train-примерах, лучшая модель выбрана по `f1_macro` на validation. Финальная оценка на test.

## 3. Данные и постановка задачи

- **Датасет**: `emotion` (dair-ai/emotion)
- **Число классов**: 6 — `sadness`, `joy`, `love`, `anger`, `fear`, `surprise`
- **Размер `train`**: 2000 (подмножество из 16000)
- **Размер `validation`**: 500 (подмножество из 2000)
- **Размер `test`**: 500 (подмножество из 2000)
- **Что именно классифицируется**: короткие твиты/высказывания, каждому присвоена одна из 6 эмоций.
- **Комментарий**: Датасет хорошо сбалансирован по основным классам (`sadness`, `joy`), тогда как редкие классы (`love`, `surprise`) встречаются реже. Тексты короткие (3–25 токенов), что позволяет использовать небольшой `max_length=128`. Классы `joy`/`love` и `sadness`/`fear` частично перекрываются по словарному составу — именно там ожидаются основные ошибки модели.

---

## 4. Токенизация и готовый инференс

### 4.1. Токенизация

- **Модель токенизатора**: `distilbert-base-uncased` (WordPiece, vocabulary size ≈ 30 522)
- **Special tokens**: `[CLS]` (id=101), `[SEP]` (id=102), `[PAD]` (id=0), `[UNK]` (id=100), `[MASK]` (id=103)
- **Padding / truncation**: показан батч из короткого и длинного текста — padding добивает короткий до длины длинного, `attention_mask=0` на `[PAD]`-позициях; truncation с `max_length=20` обрезает длинные последовательности.
- **Что показал разбор**: одно слово может разбиваться на несколько подтокенов (WordPiece); `attention_mask` обязателен для корректного игнорирования padding; итоговый вход модели — три тензора: `input_ids`, `attention_mask`, (опционально) `token_type_ids`.

### 4.2. Инференс готовой pretrained модели

- **Готовая модель**: `bhadresh-savani/distilbert-base-uncased-emotion`
- **Примеры**: 5 текстов из test-части датасета `emotion`
- **Разумность результатов**: большинство явно эмоциональных текстов предсказаны корректно; модель уверенно (score > 0.9) разделяет `sadness` vs `joy`; сложнее с `love` vs `joy` и `fear` vs `sadness`.
- **Оценка применимости**: готовая модель хорошо подходит, так как обучалась именно на этом датасете. Без дообучения для нового домена или другого набора классов её качество значительно упало бы. Высокий score ≠ гарантия правильности — на пограничных примерах модель ошибается с уверенностью ~0.6–0.7.

## 5. Fine-tuning и оценка

- **Модель для fine-tuning**: `distilbert-base-uncased`
- **Токенизация датасета**: `tokenize_batch` с `max_length=128`, `truncation=True`; `DataCollatorWithPadding` для динамического padding внутри батча
- **Максимальная длина (`max_length`)**: 128
- **Batch size**: train=16, eval=32
- **Максимальное число эпох**: 3
- **Optimizer / learning rate**: AdamW, lr=2e-5, weight_decay=0.01
- **Критерий выбора лучшего варианта**: максимальный `f1_macro` на validation-части
- **Метрики**: `accuracy`, `f1_macro`

## 7. Анализ

Разбор токенизации показал, что DistilBERT/BERT работает не со словами, а с подтокенами WordPiece: редкие слова разбиваются на фрагменты с префиксом `##`. Это важно при работе с именами собственными, числами и нестандартными формами слов.

Инференс готовой pretrained модели (`bhadresh-savani/distilbert-base-uncased-emotion`) оказался вполне полезным, поскольку она обучена именно на этом домене. Однако в реальном сценарии, если готовой доменной модели нет, такой «out-of-the-box» подход даст значительно худший результат — как показано в семинарском demo-02 на примере sentiment-модели, применённой к нетипичным текстам.

Fine-tuning улучшил ситуацию в плане контроля: мы явно разбиваем данные на train/validation/test, выбираем лучшую checkpoint по validation и единожды оцениваем на test. Это правильный экспериментальный дизайн, который позволяет избежать утечки данных и переоценки качества.

Основные ошибки модели сосредоточены на парах классов с семантическим перекрытием: `love`↔`joy` (оба позитивные), `fear`↔`sadness` (оба негативные), `surprise`↔`joy`/`fear` (может быть как положительным, так и отрицательным). Это отражает реальную сложность задачи: короткий текст не всегда однозначно указывает на одну эмоцию.

Ограничения текущей постановки: небольшой обучающий сабсет (2000 примеров), только 3 эпохи, нет подбора гиперпараметров. Для production-задачи стоит использовать полный датасет и более длительное обучение.

## 8. Итоговый вывод

В качестве базовой модели для задачи классификации эмоций на английском языке оптимален `distilbert-base-uncased`: он в 2× быстрее BERT-base при незначительной потере качества. При наличии GPU стоит рассмотреть `bert-base-uncased` или `roberta-base` для увеличения точности.

Главное понимание про токенизацию: текст не равен набору слов — токенизатор разбивает его на подслова по словарю, добавляет служебные токены и формирует три тензора (`input_ids`, `attention_mask`, `token_type_ids`). Игнорирование `attention_mask` при работе с батчами — типичная ошибка.

Главное понимание про различие между готовым инференсом и fine-tuning: готовая модель удобна для быстрой проверки гипотезы, но не гарантирует качества вне своего домена. Fine-tuning на собственных размеченных данных даёт контроль над метриками, разбивкой и выбором лучшей checkpoint — именно это является правильной инженерной практикой.
